## 3. Process and attendance boundaries

### Process A — authoring train

One fresh local Codex author process may execute G01 and G02 continuously with
an overall elapsed cap of 24 hours. If G01 ends with exact merged-dev green, it
must proceed directly into G02 instead of returning merely to request the next
prompt.

It must stop after G02 reaches a green exact-head PR because G03 requires a
fresh independent process.

### Process B — independent qualification audit

G03 runs in a fresh, non-resumed, non-forked Codex Sol process. It receives the
exact PR head and complete audit contract. It has no GitHub or repository write
authority. A model/profile fallback must be disclosed.

### Process C — author closeout

G04 adopts the clean G02 author worktree. If G03 passes, it merges normally and
verifies exact-dev. If G03 reports corrections, G04 may make one bounded
correction commit, re-run all gates, and return to a fresh G03 audit. At most two
G03/G04 correction loops are permitted.

If G05 is already complete, the same process may continue directly to G06 after
exact-dev passes. Otherwise it returns `WAITING_OWNER_INPUT`, not `BLOCKED`.

### Owner lane

G05 may run in parallel with G02/G03. G07 and G08 are separate attended goals.
G07 cannot auto-transition to G08 because `PREFLIGHT_ELIGIBLE` creates no mutation
authority. The owner must review G07 and explicitly launch G08.

### Process D — independent closeout

G09 runs in a new read-only Sol process against the exact evidence generated by
G08. It cannot repair evidence, mutate GitHub, rerun Hyper-V, or promote support.

## 4. Common launch contract

Every Goal prompt must be self-contained. It must not depend on this chat being
visible. At launch it must include:

- exact Goal ID and parent contract;
- repository, target branch, work branch/worktree when applicable;
- bounded Cargo target and `CARGO_BUILD_JOBS=4` for repository builds;
- exact live refs expected at admission;
- exact candidate/package/binary identities where relevant;
- checkpoint/evidence root unique to that Goal;
- authorized writes and mutations;
- prohibited operations;
- entry gate, success gate, stop conditions, correction budget;
- required final receipt fields;
- `REAL_PLATFORM_ACCEPTANCE`, support, main, release, and all mutation flags.

Stale planning SHAs are expectations only. Every Goal fetches or observes the
live exact state before mutation.

### Objective

Prepare one legitimate, owner-controlled Windows Server 2022 x86_64 image for

  images, or images with unclear provenance;

### Success

## 12. G08 — owner-attended real Hyper-V acceptance

```text
GOAL_ID=VMCELL-WIN-HYPERV-ONE-WEEK-G08-REAL-ACCEPTANCE
MODE=OWNER_ATTENDED_AUTHORIZED_REAL_PLATFORM
TIMEBOX=6_TO_10_HOURS
OWNER_PRESENT=true
```

### Entry authority

The owner must issue a new explicit Goal after reviewing G07. It binds exactly
one candidate, binary, image, host, state root, runtime root, evidence root,
foreign prestate, and time window. No earlier Goal grants this authority.

### Staged sequence

1. **R0 final prestate:** recheck all identities, image hash/read-only state,
   foreign inventory, exclusive window, and evidence directory.
2. **R1 image registration:** register and validate only the exact image.
3. **R2 stopped cell:** create one exact-owned networkless stopped VM and prove
   Generation 2, Secure Boot, exact overlay parent, ownership, stopped state,
   resources, one expected disk, and zero adapters before start.
4. **R3 first start:** recheck ownership, start exact VM, and prove PowerShell
   Direct readiness using interactive stdin credentials.
5. **R4 minimum command:** prove bounded stdout, stderr, zero exit, encoding,
   byte limits, timeout, and operation correlation.
6. **R5 usable function:** prove typed nonzero exit, copy-in, copy-out, artifact
   hash/correlation, and three sequential fresh-identity runs.
7. **R6 recovery:** execute exactly one preselected bounded interruption/failure
   scenario, no blind replay, and reconcile durable/actual state.
8. **R7 cleanup:** stop/remove only exact-owned resources after fresh ownership
   checks; repeat destroy to prove idempotent absence.
9. **R8 poststate:** prove no residue, unchanged base hash, and unchanged
   foreign host/provider state; generate sanitized receipts.

### Mutation ceiling

- one exact-owned VM lifecycle at a time;
- disposable differencing overlays only;
- no switch/network/firewall/feature/service/runner/ACL/base-image mutation;
- no foreign or ambiguous object adoption or deletion;
- credentials only through bounded stdin;
- immediate stop on mismatch or unknown effect.

### Success

```text
DISPOSITION=G08_REAL_RUN_COMPLETE_AWAITING_G09_AUDIT
```

G08 itself does not declare final owner-preview PASS. That belongs to G09.

## 18. Anti-stall rules

The author Goals must not stop merely because:

- required CI is pending within the eight-hour wait window;
- self-hosted R4 fails before checkout while required Hosted CI remains the
  declared correctness gate;
- Apple/HVF, Linux, QEMU, Docker, JobSpec, release, or support evidence is
  absent;
- G05 is not ready while useful G02/G03/G04 work remains;
- an expected implementation fixture fails inside the correction budget;
- an execution phase completes earlier than its timebox.

They stop only at a defined process/authority boundary or a listed real
blocker. Execution-budget interruption produces a durable `PARTIAL_RESUMABLE`
checkpoint, not a false protected-workflow classification.
