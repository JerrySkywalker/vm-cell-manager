VM Cell Manager portable GNU/Linux package
==========================================

Install
-------

1. Verify the adjacent SHA256SUMS.txt before extraction.
2. Extract the archive into a user-owned staging directory. The archive keeps
   its versioned vmcell-vX.Y.Z-linux-x86_64 top-level directory.
3. Copy `vmcell` to a user-owned prefix such as `$HOME/.local/bin/vmcell` and
   keep mode 0755. Do not use sudo for the repository-local smoke path.
4. Optionally copy `completions/vmcell.bash` to
   `$PREFIX/share/bash-completion/completions/vmcell` and
   `completions/_vmcell` to `$PREFIX/share/zsh/site-functions/_vmcell`.
5. Run `vmcell --version`, `vmcell --help`, and `vmcell doctor` before any
   provider operation.

The package does not install QEMU, repair /dev/kvm, load modules, configure
networking, start services, or grant provider authority. Real KVM/QGA execution
remains release-gated.

Upgrade
-------

1. Stop other vmcell commands using the same state root. Do not stop or remove
   provider objects merely to replace the program.
2. Keep the old binary and a recoverable copy of the state root. Registered
   immutable base images remain outside this package and must stay in place.
3. Verify and extract the new version beside the old one.
4. Run `vmcell --state-root PATH state check` with the new binary before the
   first mutating command. Stop on upgrade-required, integrity, or ambiguity.
5. Switch the user PATH and completion files only after version/help/doctor
   checks pass. Rollback selects the preserved old binary; it is not a state
   downgrade.

Remove
------

1. Inspect retained cells and operations through vmcell before deciding on any
   provider cleanup. Never delete a VM by name or PID alone.
2. Remove only the installed vmcell binary, completion files, and now-empty
   versioned program directory.
3. Leave state roots, registered images, cells, and artifacts unchanged unless
   separately reviewed operator action authorizes their cleanup.

Removing this portable package is intentionally not a data or provider cleanup
operation.
